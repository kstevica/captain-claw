# RealmCraft — Code Map

## OVERVIEW (2026-07-03)

**RealmCraft** is a single-file HTML/CSS/JS RTS game (1,571 lines, `index.html`) inspired by Warcraft/StarCraft. The player builds structures, trains units, gathers gold/wood, and manages food-population on a 64×64 tile map. No AI opponents, no multiplayer, no sound. Runs entirely in-browser with no external dependencies.

### Architecture Layers (bottom-up, 10 layers)
1. **Constants & Config** (line 86) — TILE_SIZE=32, MAP 64×64, TERRAIN enum (5 types), BUILDING_DEFS (7), UNIT_DEFS (4), TERRAIN_COLORS
2. **Game State** (line 122) — `const game = {...}` single state object: entities Map, resources, selectedIds Set, camera, ui mode, mouse, particles, floatingTexts
3. **Helpers** (line 142) — `genId()`, `dist()`, `clamp()`, `lerp()`, `rectsOverlap()`, `tileAt()`, `isPassable()`, `spawnParticles()`, `showFeedback()`
4. **Map Generation** (line 176) — `generateMap()` with seed 42: grass base, dirt paths, water bodies, tree clusters, 8 gold mines. Deterministic procedural
5. **Entity Creation** (line 262) — `createUnit(type, x, y)` and `createBuilding(type, x, y, progress)` factories
6. **Rendering** (line 297–624) — Canvas drawing pipeline: drawHealthBar → drawSelectionCircle → drawUnit (geometric shapes per unit type) → drawBuilding → render (terrain→buildings→units→selection→UI→minimap). Minimap render separate at line 625
7. **Camera** — Edge-scroll (10px zone), middle-click drag, zoom lerp (0.5×–2.0×), transform clamped to world bounds
8. **Input & Selection** (line 655) — screenToWorld/worldToScreen transforms, entityAtWorld hit-test, entitiesInRect for box-select, findNearestDropoff, findNearestResource, isPlacementValid validation
9. **Game Logic** (line 900) — `update(dt)` → `updateEntity(e, dt, toRemove)` per-entity: movement steering (lerp to target), resource gathering (mine→return→deposit loop), building construction progress, training queue, attack (target selection + cooldown), death/cleanup, particle lifecycle
10. **UI & Events** (line 1183–1567) — `updateUI()` rebuilds info/action panels, `resizeCanvas()` responsive resize, mouse handlers (mousedown/move/up/click/contextmenu/wheel), keyboard (A/S/H/Escape), minimap click pan, `initGame()` bootstrap, `gameLoop()` rAF loop

### Key Design Patterns
- **Flat JS objects** for entities (no classes, no ECS library)
- **Map<string, Entity>** for entity storage, simple iteration
- **Camera-relative rendering** via ctx.translate + ctx.scale
- **Delta-time game loop** rAF with dt cap at 50ms
- **State machine** per entity (idle/moving/attacking/gathering/building/constructing)
- **Procedural geometric graphics** — no spritesheets

### Entity Shape (flat JS object)
**Shared fields:** `{id, type, owner, x, y(world center), w, h, hp, maxHp, state, attackDamage, attackRange, attackCooldown, attackTimer, targetId, moveTarget, path, isBuilding}`
**Unit extras:** `speed, canGather, canBuild, food, size, ranged, faceDir, carryAmount, carryType, gatheringNode, gatheringTimer, buildTarget`
**Building extras:** `progress (0-1), produces[], queue[], queueTimer, queueTotal, rallyPoint, dropoff, dropoff_gold, dropoff_wood, provides[], blocking`

### UI Data Flow
1. `updateUI()` (line 1184) called every frame after game logic update
2. Reads `game.selectedIds` → if 1 entity: shows name, HP bar, stats; if multiple: count + avg HP
3. Builds action buttons based on selected entity type:
   - Building selected → "Train [unit]" buttons per `produces[]`
   - Peasant selected → "Build [building]" buttons for all 7 types
   - Military selected → "Stop" button
4. Top bar resources updated from `game.resources` + timer from `game.time`
5. Minimap redrawn each frame with colored terrain dots + entity dots
